# 是正レビュー記録

## 目的

2026-09-09の厳格レビューで指摘された実験基盤と実運用基盤の乖離を是正し、コード・仕様・主張を一致させる。

## 今回までの是正

### 1. Association Engineの実体化

観測済みシグナルから候補を生成し、暫定紐付けと未分類を返すEngineを追加した。

### 2. 曖昧性制御の強化

絶対confidenceだけでなく候補間marginを導入した。閾値以上でも競合候補との差が小さい場合はUNASSIGNEDとする。

### 3. Evidence lineage

EvidenceRefにsource type / source ID / observed time / captured time / content hash / extractor version / security classification / provenanceを持たせた。Raw source contentはEvidenceRefに保存しない。

### 4. Evidence → WorkTrace境界

観測済みEvidenceからWorkTraceを生成する取り込み境界を追加した。取り込み処理ではWork Itemへの推定を行わない。

### 5. Assignmentの非破壊化

確認時はpredictionを維持し、訂正時も元のpredictionを上書きしない。訂正後のWork Itemと訂正履歴を分離して保持する。

### 6. Knowledgeの人間承認ゲート

FACT / ANALYSISからKnowledge候補を生成できるが、自動でvalidatedへ昇格しない。validated_by / validated_atによる明示的な人間承認を必須化した。

### 7. 永続化

SQLiteによるローカル永続化層を追加した。Work Item / Work Traceを保存でき、Evidence ID・provenance・機密区分・extractor versionを保持する。

### 8. 実験結果の自己申告排除

CSVのresultを集計根拠にせず、prediction / expected / confidenceからGO / GRAY / STOPを再計算する。入力resultとの不一致は拒否する。

## 残る実運用上の未実装境界

- メール・チャット・ファイル等の具体的な外部コネクタ
- 実運用UIと未分類トレイ
- 複数ソースのEvidence重複排除・更新検知
- FACT → ANALYSISの実データ生成パイプライン
- Capability Profileの統計モデル
- 実データによる有効性・記録負担検証

これらは架空データで埋めず、実データが取得できる段階で検証する。

## 判定基準

「完成」は実装範囲を明示して使用する。CI成功を実運用有効性の証明とは扱わない。

実仕事データの性能実証値をfixtureから推定しない。
