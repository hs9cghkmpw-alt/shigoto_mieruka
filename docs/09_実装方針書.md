# Work Memory / Work Trace
## 実装方針書

**文書ステータス：Draft 0.2**  
**目的：設計を実装可能な最小単位へ落とす**

---

## 1. 実装方針

最初から完成品を作らず、実証実験を回せる最小実装を優先する。

```text
データモデル
  ↓
手動Work Item
  ↓
Work Trace入力
  ↓
ルールベース暫定紐付け
  ↓
訂正
  ↓
実験ログ集計
  ↓
実測
  ↓
必要箇所だけ高度化
```

AIによる意味理解は初期実装の必須条件にしない。

## 2. 技術方針

初期の実験・評価ツールはPythonを候補とする。これは暫定方針であり、UIや本番バックエンドの技術選定を固定するものではない。

データモデルは特定DBへ強く依存しない。

## 3. 最小コンポーネント

### 3.1 Domain Model

WorkItem、WorkTrace、Fact、Analysis、Knowledge、Rework、AssignmentCorrection、SecurityClassification、Provenanceを表現する。

### 3.2 Association Engine

まずルールベースで候補Work Itemをスコアリングする。

強いシグナルを優先し、低信頼度の場合は未分類とする。候補が同点の場合も自動紐付けせず未分類とする。

### 3.3 Experiment Aggregator

experiment_log.csvを読み込み、GO / GRAY / STOP判定と基本集計を行う。

### 3.4 Test Fixtures

通常ケース、弱信号、信号なし、同点候補、高信頼度の誤紐付けを含む決定論的な実験データを用意する。

## 4. 実装順序

1. 型定義・Domain Model
2. Work Item / Work Traceの生成・検証基盤
3. Association Engineの最小版
4. 実験ログ集計
5. 単体テスト
6. CI
7. 決定論的安全性実験
8. 実データによる10件実験
9. 実験結果に基づく改善

## 5. 設計原則の実装上の扱い

- observedとreportedを混同しない
- ANALYSISはFACTを上書きしない
- KNOWLEDGEは人間承認なしに確定しない
- 誤紐付けより未分類を優先する
- セキュリティ分類を派生データへ継承する
- 訂正履歴を消さない
- 記録負担を実測する

## 6. 初期実装でやらないこと

- 全PC操作の監視
- 常時スクリーン監視
- 無制限の外部AI送信
- 自動人事評価
- 人物ランキング
- 完全自動Knowledge昇格
- 高度なダッシュボード

## 7. 完了条件

最初の実装フェーズは、以下を満たした時点で完了とする。

- Work Itemを登録できる
- Work Traceを登録できる
- Work Traceに暫定Work Itemを付与できる
- 未分類として保持できる
- 訂正結果を記録できる
- 実験ログを集計できる
- GO / GRAY / STOPを再現可能なルールで判定できる
- 同点候補を安全に未分類へ送れる
- セキュリティ分類を派生データへ継承できる
- 訂正前後を別レコードとして保持できる
- 単体テストが通る

この段階では「就労能力プロファイルの完成」ではなく、「実際の仕事データを安全に取得・整理・検証できること」を成功条件とする。
