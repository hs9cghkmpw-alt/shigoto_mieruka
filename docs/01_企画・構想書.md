# Work Memory / Work Trace
## 企画・構想書

**文書ステータス：Draft 0.1**  
**最終目的：就労能力の可視化**

---

## 1. プロジェクト概要

Work Memory / Work Traceは、個人が実際の仕事を行った際に発生する作業履歴を記録・整理・分析し、「その人が仕事の中で何ができるのか」「何に時間がかかるのか」「どのような条件で能力を発揮できるのか」を可視化するための仕組みである。

単純な勤怠管理や作業時間計測を目的とせず、以下のような実際の仕事プロセスを記録する。

- 何の仕事をしたか
- どの工程にどれだけ時間を使ったか
- どのように情報を探したか
- 誰に何を聞いたか
- どのような情報を入力・整理したか
- どこで作業が止まったか
- 何が原因で時間がかかったか
- どの程度の支援が必要だったか
- 手戻りや再作業が発生したか
- 経験によって作業が改善したか

蓄積されたデータを分析し、最終的に個人ごとの「就労能力プロファイル」を形成する。

## 2. 最終目的

### 2.1 就労能力の可視化

本プロジェクトの最終目的は、**個人の実際の仕事データから、その人の就労能力・適性・必要な支援・能力を発揮しやすい条件を可視化すること**である。

「できる／できない」という二値的な評価ではなく、**何を、どの条件で、どの程度、どのような支援を受けながら、どの程度の時間・品質で遂行できるか**を捉える。

## 3. 背景・課題

現在の就労能力の把握は、本人への聞き取り、支援者による観察、面談、実習、上司・人事による評価など、人間による主観的な評価に依存する部分が大きい。

その結果、以下の問題が発生する。

1. 「できる」の中身が分からない
2. 作業時間だけでは能力を判断できない
3. 本人・支援者・職場の認識が一致しない
4. 本人に必要な支援が曖昧になる
5. 支援の効果が測定しにくい
6. 本人に合った仕事・環境が分からない
7. 同じ問題が繰り返されても経験が再利用可能な知識にならない

## 4. 想定利用者

### 4.1 本人

得意な作業、苦手な作業、時間がかかる工程、能力を発揮しやすい環境、必要な支援、習熟による改善などを確認する。

### 4.2 就労支援者

本人が「何ができないか」ではなく、「どの条件なら能力を発揮できるか」を把握するために利用する。

### 4.3 企業・上司

業務分担、タスク設計、合理的配慮、業務環境調整、OJT、配属等の補助情報として利用する。

### 4.4 人事

採用・配置・育成・評価における補助データとして利用する。ただし、単純な作業時間ランキングや監視目的での利用は本システムの思想から除外する。

## 5. 基本思想

### 原則1：人間の記録作業を増やさない

記録するための仕事が増えれば、本来の目的から逸脱する。自動取得、短文入力、音声入力、AI整理等を優先する。

### 原則2：人ではなく仕事のプロセスを分析する

個人監視を目的とせず、作業プロセスと能力発揮条件を分析する。

### 原則3：事実とAIの推測を分離する

FACTとANALYSISを混同しない。

### 原則4：AIに人間の評価を丸投げしない

AIは分析・候補提示を行い、重要な判断には人間を介在させる。

### 原則5：機密情報を無制限に外部AIへ送らない

セキュリティ分類とデータ処理経路を管理する。

### 原則6：「遅い＝能力が低い」と判断しない

作業時間だけでなく、難易度、品質、支援、環境、手戻り、習熟などを含めて評価する。

## 6. データの基本構造

Work Traceでは、情報を以下の3層に分離する。

### FACT
実際に起きたこと。観測データまたは本人申告として保存する。

### ANALYSIS
AI等による分析・仮説。FACTを書き換えない。

### KNOWLEDGE
繰り返し確認され、人間による検証を経て再利用可能な知識として昇格したもの。

FACTの出所は、`observed`（システム等から観測）と`reported`（本人等から申告）を区別する。矛盾があればどちらかを黙って上書きせず、要確認として保持する。

## 7. Work Item

記録の中心単位をWork Itemとする。

対象には以下を含む。

- プロジェクト
- 案件
- タスク
- 依頼
- 電話
- メール
- 調査
- 文書閲覧
- 他者からの依頼
- 割り込み
- フォローアップ
- 複数日にまたがる作業

Work Itemには、開始・終了時刻、参照資料、質問・相談、回答待ち、割り込み、遅延理由、返信、完了条件、手戻り等を関連付ける。

## 8. 自動紐付け

本プロジェクトにおける最大の技術的ゲートは、イベントを正しいWork Itemへ関連付けることである。

自動取得そのものよりも、電話、割り込み、並行案件等を含むイベントの意味的な紐付けが難しい。

基本方針：

- 直近のアクティブWork Itemを暫定候補にする
- メール件名・スレッド・チャット・文書等を強い手掛かりとする
- 電話等で紐付け不能なものは未分類トレイへ送る
- ワンタップ訂正を可能にする
- 後から一括紐付けできるようにする
- 音声文字起こしは下書きとして扱い、短時間で確認できるようにする

## 9. 処理モデル

完全な直列処理ではなく、継続的なスパイラル型処理を採用する。

1. 記録対象か判定
2. Work Itemへ暫定紐付け
3. 機密区分を判定
4. AI処理可否を判定
5. AI分析
6. 必要に応じて紐付けを修正
7. 知識候補を生成
8. 人間が検証
9. KNOWLEDGEへ昇格

ログ取得・紐付け・機密性判定・許可されたAI処理は可能な限りリアルタイムで行い、知識昇格等は非同期処理とする。

## 10. セキュリティ

外部AIをデフォルト利用とはしない。企業・個人の機密情報を扱う可能性があるため、データ分類ゲートウェイを設ける。

- 生ログとAI分析用データを分離
- 機密データは内部AI・ローカルAIのみ、またはAI処理禁止
- 外部AIは許可されたデータのみ
- アクセス制御
- 監査ログ
- 保持期間管理
- AIバックエンド交換可能な設計
- ポリシーエンジンによる自動ルーティング
- KNOWLEDGEには元データのセキュリティ区分を継承

最小実験では外部AIをデフォルトOFFとする。Brain Twinとの全面統合は実験対象外とし、セキュリティラベル継承のみデータモデルに確保する。

## 11. 就労能力プロファイル

将来的には、以下の観点を組み合わせて個人の就労能力を可視化する。

- 仕事の種類別パフォーマンス
- 工程別時間
- 情報収集・検索方法
- 質問・相談方法
- 情報整理・入力
- 再作業・手戻り
- 割り込みからの復帰
- 並行案件への対応
- 品質
- 速度
- 学習・習熟
- 支援量
- 環境適合性
- 支援による改善効果

重要なのは単一スコア化ではなく、**能力・環境・支援の組み合わせを可視化すること**である。

## 12. 支援効果の測定

例えば、支援前に資料整理が40分かかり、支援方法を変更した結果22分になった場合、作業時間が18分短縮されたと測定できる。

これにより「本人の能力」だけではなく、「どの支援が能力発揮に有効だったか」を評価できる。

## 13. 実証実験

初期実験では10 Work Itemsを対象とする。これは統計的な最終検証ではなく、技術的成立性を判定するスクリーニングである。

対象パターン：

1. 電話
2. メール
3. 文書閲覧
4. Web調査
5. 他者依頼
6. 割り込み
7. 並行案件
8. 完了フォロー
9. 複数日

10件のため、1パターンを2件、残りを各1件とする。初期案では電話を2件とする。

### GO / STOP基準

| 指標 | GO | STOP |
|---|---:|---:|
| 自動紐付け成功 | 7/10以上 | 5/10以下 |
| 誤紐付け | 1件以下 | 3件以上 |
| 平均訂正時間 | 10秒以下 | 20秒以上 |
| 未分類率 | 30%以下 | 50%以上 |

中間領域はグレーゾーンとし、20件まで拡張する。

また、全体値がGOでも特定パターンで重大な失敗が集中している場合は、パターン別評価を優先してSTOP判断できるものとする。

## 14. 再作業・手戻り

再作業・手戻り件数を重要な能力分析指標として扱う。

ただし、手戻りを本人の能力不足と単純解釈せず、以下を含めて分析する。

- 情報不足
- 指示の曖昧さ
- 他者回答待ち
- 環境要因
- 割り込み
- 習熟不足
- 作業設計上の問題

## 15. 人事評価への利用に関する原則

本システムは、人事評価を目的の一つとして利用できる可能性があるが、単純なランキングや作業時間のみの評価には使用しない。

評価する場合は、少なくとも以下を組み合わせる。

- 作業量
- 難易度
- 品質
- 作業時間
- 支援量
- 手戻り
- 環境条件
- 習熟度
- 改善度

また、企業導入時には従業員監視、プライバシー、労務・法務上の論点を別途検討する。

## 16. Out of Scope

初期段階では以下を対象外とする。

- 全社規模の従業員監視
- 人事評価のみを目的とした利用
- 従業員ランキング
- 生産性ランキング
- 全活動の完全自動意味理解
- 無制限の外部AI利用
- 最小実験段階でのBrain Twin全面統合
- 高度なダッシュボード
- 自動的なKnowledge昇格
- PC操作の全面監視

## 17. 現在の開発フェーズ

本プロジェクトは、机上での仕様レビューを複数回実施済みであり、Work Item自動紐付けが最大の技術的ゲートであることが繰り返し確認されている。

したがって、仕様検討を無制限に継続するのではなく、**実データによる実証実験へ移行する。**

実験結果から実際の問題が発見された場合にのみ仕様を改訂する。

## 18. 最終ビジョン

Work Memory / Work Traceは、最終的に以下の流れを実現する。

```text
本人の認識
    ＋
支援者の観察
    ＋
職場での評価
    ＋
実際のWork Trace
        ↓
データ統合・分析
        ↓
就労能力プロファイル
        ↓
仕事・環境・支援の適合条件を発見
        ↓
業務設計・合理的配慮・就労支援へ反映
        ↓
結果を再びWork Traceへ蓄積
```

本プロジェクトの本質は、個人を評価することではなく、**人と仕事と環境と支援の適合関係をデータから発見すること**にある。
