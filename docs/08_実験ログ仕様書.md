# Work Memory / Work Trace
## 実験ログ仕様書

**文書ステータス：Draft 0.1**

---

## 1. 目的

実証実験で取得するWork Traceと評価結果を、後から再検証できる形で保存する。

## 2. 原則

- 追記型
- 1イベント1行を基本とする
- 推測値と観測値を混同しない
- 訂正前後を追跡可能にする
- 実測時間を優先する
- 実験後の基準変更を許可しない

## 3. 必須フィールド

| フィールド | 内容 |
|---|---|
| id | 連番ID |
| pattern | 実験パターン |
| date_time | 発生日時 |
| expected_work_item | 正解Work Item |
| auto_assigned_work_item | 自動割当結果 |
| association_correct | 正誤 |
| wrong_assignment | 誤紐付け有無 |
| unclassified | 未分類有無 |
| correction_start/end | 訂正時間測定区間 |
| correction_seconds | 訂正秒数 |
| additional_recording_start/end | 追加記録時間測定区間 |
| additional_recording_seconds | 追加記録秒数 |
| rework_count | 手戻り件数 |
| reuse_or_improvement_value | 再利用・改善価値 |
| observed_reported_conflict | observed/reported矛盾 |
| security_classification | 機密区分 |
| notes | 補足 |

## 4. 判定値

`association_correct` は、少なくとも `true / false / unknown` を扱える設計とする。

未分類は誤紐付けと区別する。

## 5. 時間計測

訂正時間と追加記録時間は、開始・終了時刻と算出秒数を保存する。

算出値と元時刻の双方を残すことで再計算可能にする。

## 6. セキュリティ

実験ログにもセキュリティ分類を付与する。

機密データをテスト用外部AIへ投入しない。

## 7. 変更管理

既存行を上書きして実験履歴を消さない。

訂正が必要な場合は、訂正イベントまたは変更履歴として追跡可能にする。
